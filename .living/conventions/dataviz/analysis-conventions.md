# Data Visualization Conventions (dataviz)

Data-visualization conventions for analytical work in this repository. These
govern every figure produced for ordinations, differential analyses, and
multivariate summaries so that figures are honest, reproducible, accessible,
and self-describing.

## Ordinations (PCA / PCoA / PLS-DA / t-SNE / UMAP)

1. **Always report variance explained.** Axis labels must carry the percent
   variance explained (e.g. `PC1 (28.3%)`) wherever the method provides it
   (PCA, PCoA decomposition of a distance matrix with eigenvalues, etc.).
   For methods without a variance metric (t-SNE/UMAP), say so in the caption
   and instead report the number of neighbors / perplexity / random seed.
2. **Ellipses are optional and must be explicit.** If confidence ellipses are
   drawn, state the level (e.g. 95%) and the method (ellipse is a
   `t`-distribution-based confidence region of the group centroid, *not* a
   data scatter blob). Never present a centroid ellipse as evidence of
   separation without a companion null/permutation test.
3. **Rotation and sign are not meaningful.** PCA/PCoA axes are arbitrary up to
   sign and rotation; never interpret "PC1+ direction = X" biologically.
   Report loadings/contributions separately when a feature-level story is
   needed.
4. **Scale honestly.** Prefer symmetric axis limits when a centered origin is
   informative (e.g. PCA score plots). Unit-equal scaling (`asp=1`) on both
   axes is expected so distances are not visually distorted.
5. **Overplotting is handled, not hidden.** For many samples use transparency
   (alpha), jitter for categorical scatter, or faceting. Never rely on color
   alone to separate overlapping clusters.

## Color

1. **Colorblind-safe by default.** Use OKLCH/tab10/`Okabe-Ito`-style palettes;
   avoid red/green contrasts. Verify figures under a deuteranopia/protanopia
   simulation (e.g. `colorspace::simulate_cvd` in R, `colorblindr`).
2. **Sequential vs categorical.** Use sequential (single-hue) scales for
   continuous values, categorical palettes for groups, and never combine them
   implicitly.
3. **Direction is meaningful.** When a diverging scale (e.g. log2FC) is used,
   the midpoint = 0 must fall exactly at the neutral color.
4. **Smart default palette set.** Keep one repo-wide categorical palette
   constant across figures (e.g. defined once in a shared `theme/` helper) so
   the same group looks the same in every figure.

## Reproducibility

1. **Every figure has a script.** Figures must be generated by a committed
   script (`run.py`, `figure_X.R`, or a notebook that is executed end-to-end)
   — never by hand. Each analysis folder's `run.sh`/`run.py` must regenerate
   the figures.
2. **Fix the seed.** Any stochastic step (t-SNE, UMAP, bootstraps, jitter,
   MCMC-based ordination) pins `set.seed`/`numpy.random.seed`/`random_state`
   and records it in the figure caption or a sidecar params file.
3. **Embed provenance in file name or sidecar.** Figures default to
   `<analysis>_<metric>_<date>.{pdf,png,svg}` and may carry a YAML/JSON
   sidecar with contributing script path, input table hash, params, and
   software versions when the convention is enabled.
4. **Version inputs.** Record the hash/version of the input feature table or
   quant matrix in a `figures/` sidecar or `LOG_REGISTRY.md` entry so a figure
   can be traced to a specific data snapshot.

## Output formats

1. **Vector preferred for print.** Use `.pdf` or `.svg` for publication
   figures; `.png` at ≥300 dpi only where a raster is required.
2. **Fixed-size fonts.** Set text sizes explicitly (never default autoscale) so
   axes/legends survive downscaling for slides.
3. **Legends are explicit.** Group legends include n per group
   (e.g. `spore (n=33)`).

## QC before a figure ships

- [ ] Axis labels include variance explained where applicable
- [ ] Palette is colorblind-safe; no red/green contrast
- [ ] `set.seed`/`random_state` pinned for stochastic methods
- [ ] Script that made the figure is committed and re-runs cleanly
- [ ] n per group stated in legend or caption
- [ ] Data points not hidden under an opaque layer
