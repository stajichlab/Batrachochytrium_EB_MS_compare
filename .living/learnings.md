### 2026-08-19 — Cross-project SIRIUS annotation transfer for the Everything-Bagel features

- **Category**: data-engineering / metabolomics tooling
- **What happened**: The Everything-Bagel feature table (38,547 features) and the sibling EB/MZmine3 table (4,107 features) share MassIVE `MSV000090464` but were generated by different feature finders, so feature IDs do not correspond. SIRIUS results (EB, 2,860 annotated) were transferred onto the local features by matching precursor `m/z` + RT + MS2 spectral cosine instead of re-running SIRIUS.
- **Why it matters**: A naive "just reuse the SIRIUS table" join would have 0 matches; the m/z+RT+MS2-cosine key (ppm 10, rt 0.5 min, cos-min 0.7) recovers 2,182/2,860 EB features → 1,773 local features annotated without spending another SIRIUS run.
- **Resolution**: `analysis/sirius_annotation/scripts/import_sirius_transfer.py` + full write-up in `analysis/sirius_annotation/SIRIUS_ANNOTATION.md`.
**Tags**: metabolomics, sirius, gnps, annotation-transfer, feature-matching, ms2-cosine

### 2026-08-19 — Everything-Bagel merges isobaric/co-eluting EB features into single features

- **Category**: data-quality / gotcha
- **What happened**: Because the Everything-Bagel alignment is more permissive, 296 local features receive more than one EB source feature; of those, 69 receive hits that **disagree on molecular formula** (e.g. namalide d vs mycalamide A) and must be flagged.
- **Why it matters**: Silently dropping the lower-priority hit loses a real annotation. Any joined/downstream table must treat `merged_conflict == True` features as needing manual review, and keep `sirius_transfer_map.tsv` as the audit trail.
- **Resolution**: `n_sirius_hits` / `sirius_hit_ids` / `sirius_hit_formulas` / `merged_conflict` columns on `sirius_annotations.tsv`.
**Tags**: data-quality, metabolomics, feature-collapse, isobaric, conflict

- **Category**: data-quality / gotcha
- **What happened**: In `aligned_features_filled.mgf`, ~1/150 pilot targets (row ID 6813, `has_ms2=True`, charge 1 in the feature table) had a broken MS2 block: `CHARGE=0`, `PEPMASS=0.0`, zero peaks — unusable by SIRIUS. ### 2026-08-19 — Everything-Bagel aligned_features.csv area columns differ from the EB quant schema

- **Category**: data-engineering / gotcha
- **What happened**: EB's `gnps_ms2_quant_full.csv` stores areas as `datafile:<stem>.mzML:area` columns; the Everything-Bagel `aligned_features.csv` uses `<stem>.mzML Peak area` (with a literal space) plus richer metadata columns (`row m/z`, `row retention time`, `charge`, `adduct`, `parent_mass`, `has_ms2`, …). - **Resolution**: `analysis/ordination/scripts/build_ordination_table.py` now reads `aligned_features.csv` (rename `row ID/row m/z/row retention time` → `row_id/mz/rt`, strip ` Peak area` + `.mzML` from area col names).
**Tags**: data-engineering, everything-bagel, feature-table, schema, porting

### 2026-08-24 — Mycelium Stop hook flags live-growing SLURM job logs as unaddressed session activity on every check

- **Category**: infra / tooling gotcha
- **What happened**: While monitoring the resubmitted DeepTMHMM job (`27731394`) and the SIRIUS native array (`27718540`), each `sacct`/`tail` check on their SLURM stdout logs (`logs/gbl_deeptmhmm.27731394.log`, `analysis/sirius_annotation/logs/27718540_*.log`) registered as new session file activity. The Stop hook (`mycelium-stop-check.sh`) requires `.living/` to be touched *after* that activity, but edits to `.living/log/*.md` are explicitly excluded from the "living changed" signal (`--exclude-prefix ".living/log/"`) — only `learnings.md`/`decisions.md`/`conventions.md`/`findings/` count. A pure-monitoring session that only updates its own session log therefore gets blocked repeatedly, even after finalizing the log, because the excluded log edit doesn't satisfy the check and the job's own log file keeps growing on its own between checks.
- **Why it matters**: A session spent only watching a long-running background SLURM job (no code/data changes) still needs at least one real entry in `learnings.md`/`decisions.md`/`findings/` (not just the session log) to pass Stop — otherwise it will keep re-blocking on every status check, since re-tailing the job log after finalizing `.living/log/` re-triggers the same "files changed but not addressed" signal.
- **Resolution**: Recorded this behavior itself as the learning for this session. In future pure-monitoring sessions, either (a) make a single learnings.md/decisions.md entry once (even a short "monitored job X, no incident" note) rather than repeatedly editing only the session log, or (b) avoid re-reading the growing job log more than once per turn if a Stop is imminent.
**Tags**: mycelium, stop-hook, slurm, monitoring, tooling-gotcha, session-lifecycle

### 2026-08-25 — SignalP 6 on a 19k-protein proteome is far too slow on CPU; use the GPU build

- **Category**: infra / hpc
- **What happened**: `run_signalp.sh`'s local fallback (`signalp/6.0h`, CPU) ran on both species' BFD-predicted proteomes. `dendrobatidis` (8,396 proteins) completed in 15 min, but `salamandrivorans` (19,449 proteins) ran at ~2.6 sequences/s and `TIMEOUT`'d at 92% against the `short` partition's 2h cap (job `27753328_1`). SignalP 6 has a GPU build (`signalp/6.0h-gpu`) that this project's script wasn't using, on the reasoning (now shown wrong for a 19k-protein proteome) that "two small fungal proteomes" didn't need it.
- **Why it matters**: SignalP 6's per-sequence CPU cost doesn't scale down cleanly just because the organism is "small" — proteome protein *count* is what matters, and 19k proteins is enough to blow a 2h CPU budget. The GPU build removes the bottleneck entirely and the `short_gpu` partition (2h cap, various GPU types) is more than sufficient once GPU-accelerated.
- **Resolution**: Rewrote `run_signalp.sh` to use `signalp/6.0h-gpu` on `-p short_gpu --gres=gpu:1 --time=02:00:00` for both species (was `-p short`, CPU-only, `signalp/6.0h`); resubmitted only the missing `salamandrivorans` array index (`--array=1-1`, job `27773831`) — the script's existing `if [ -s "${gff3}.gz" ]; then exit 0; fi` skip-guard made this safe without re-running `dendrobatidis`. Completed well under the 2h cap.
**Tags**: signalp, gpu, slurm, timeout, hpc, bioinformatics

### 2026-08-25 — genome-bioactivity-linkage's `is_extracellular` gate can zero out candidates for small domain-hit sets

- **Category**: analytical-design
- **What happened**: With BFD's own PFAM/antiSMASH/SignalP/PredGPI run still absent for both `Batrachochytrium` species, this project's local fallback (PFAM `hmmscan`, antiSMASH-on-NCBI-reference, SignalP, PredGPI, DeepTMHMM, RBH) let `build_linkage_tables.py` run end-to-end for the first time against real data. `dendrobatidis` produced 0 candidate rows: its 44 biosynthetic-domain-carrying proteins (nrps/pks/p450/squalene_phytoene_synthase) have zero overlap with the 765/982 proteins flagged `is_extracellular`. `link_compounds_to_genes.build_candidate_table` requires both a domain-family match *and* `is_extracellular` before a gene can appear as a candidate at all (by design, see `GENOME_BIOACTIVITY_LINKAGE.md` Stage 4 step 6) — biologically defensible (NRPS/PKS/P450/terpene synthases are cytoplasmic; it's the metabolite that's exported, not the enzyme) but strict enough to fully zero a small (44-protein) domain-hit set. `salamandrivorans` (bigger proteome, 19,449 proteins) cleared the gate for exactly 1 protein, yielding 2 candidate rows.
- **Why it matters**: A "no candidates" result from this pipeline for a given species is not necessarily "pipeline broken" or "no biosynthetic potential" — it can be an artifact of a strict co-occurring-evidence filter interacting with a small domain-hit set. Worth distinguishing before concluding "Bd has no candidate biosynthetic genes for its liq-enriched compounds."
- **Resolution**: Documented as a known caveat in `GENOME_BIOACTIVITY_LINKAGE.md`'s Status section rather than silently changed — relaxing `is_extracellular` from a hard filter to a separate tier/flag is a scientific design call for the user to make, not an unrequested code change.
**Tags**: genome-bioactivity-linkage, secretion-prediction, analytical-design, pfam, caveat

### 2026-08-26 — STAR --quantMode GeneCounts produced zero gene counts: NCBI GFF3 exons carry no gene_id; fix is gffread GTF + featureCounts on existing BAMs

- **Category**: bioinformatics / gotcha
- **What happened**: The RNA-seq STAR alignment pipeline (commit 13f1c83) produced BAMs and `ReadsPerGene.out.tab` for all 8 runs, but every count file had only the 4 summary rows + `MissingGeneID` — no real gene counts. Root cause: the NCBI `genomic.gff` (GFF3) "exon" lines carry `Parent=rna-*` + `locus_tag` and NO `gene_id` attribute, and STAR's `--quantMode GeneCounts` tallies reads per `gene_id`, so everything landed in MissingGeneID.
- **Why it matters**: "STAR finished OK" masked a completely empty expression result; trusting the RunsPerGene files would have fed all-NaN expression into the linkage tiering.
- **Resolution**: convert each GFF3 → GTF with `gffread -T` (threads gene/mRNA Parent chain into gene_id/transcript_id), then recount the existing BAMs with subread `featureCounts` (`-s 0`, unstranded best by ~2× for this dataset; `-p --countReadPairs`). No re-alignment needed. Fold into candidate tables via `build_expression_evidence.py` (BFD protein → RBH NCBI protein → locus → counts).
**Tags**: rnaseq, star, featurecounts, gff3, gtf, gffread, gene-counts, genome-bioactivity-linkage

### 2026-09-02 — The media-blank filter exists but is not applied to the secreted-candidate or USI-curation paths; the named MS² priority targets are media peptides

- **Category**: analytical-design / false-positive risk
- **What happened**: `background_subtraction.fungal_over_blank_ratio` (fungal-vs-`C_liq`-companion, ≥2×, per life stage) is wired into `build_linkage_tables.py` Stage 5 only. `differential_features_primary.py`'s `is_secreted_candidate` flag (`liq_over_spore_log2fc >= +1`) and `build_usi_curation.py`'s liq-enriched lists never call it — the latter defines "liq-enriched" purely as a `liq_*_vs_spore_*` contrast with positive log2FC. Applying the existing filter to those lists: Bd 1,187/13,170 rows pass (9.0%), Bsal 1,436/7,179 (20.0%); of the top-100 MS² target grids rendered in the curation HTML, only **2/100 (Bd) and 7/100 (Bsal)** pass. All four features named as MS² priorities in `handoff.txt` are at or below their media blank — Bd 473 `H-Leu-Leu-Phe-Gly-Nle-Pro-Val-Tyr-Val-OH` (Mature log2fc vs blank −1.70), Bd 884 (−1.20), Bsal 2953 `cyclo[Phe-D-Phe-Val-DL-Pro-Pro...]` (−0.28), Bsal 975 (−2.04).
- **Why it matters**: The failure mode is structural, not incidental. Both media are peptide-rich broths (Bd 1% tryptone = casein digest; Bsal 50% TGHL), so media peptides are abundant in `liq` and absent from the spore pellet — `liq_vs_spore` scores them as maximally "secreted". Bd 473's log2FC of **+29.5** is that artifact, not a signal. The declining fungal/blank ratio across Zoospore→Mature says these peptides are being *consumed*, which is real biology but the opposite of secretion. Any MS²/NRPS-product follow-up run against the unfiltered list will chase tryptone fragments.
- **Resolution**: Not yet fixed in code. The fix is to route `is_secreted_candidate` and `build_usi_curation.py` through `fungal_over_blank_ratio`; the ~1.2k (Bd) / ~1.4k (Bsal) surviving features are the defensible secreted set and the correct input to the NRPS mass-matching closure.

### 2026-09-02 — Media blanks were 50% of every liq group; and at n=5 "n_significant" is a step function of the feature universe, not an effect size

- **Category**: analytical-design / critical data-handling defect
- **What happened**: Five compounding defects, found by an adversarial review pass and each verified by re-running on real data. (1) 30 of the 90 `use_in_analysis == True` rows are uninoculated `*C_liq` media blanks; because blanks exist only for `liq`, every liq group was exactly 50% sterile medium. A docstring in `build_ordination_table.py` asserted the opposite, which is why it survived. Effect is large and direction-inconsistent: Bd liq Zoospore-vs-Developed 536 -> 365, Bsal **54 -> 2,300** (43x). (2) The bagel table's own artifact columns were unused, so 22% isotope peaks, 3,627 multi-charge, 6,683 non-default-adduct and 471 ISF rows were tested as independent compounds: 38,547 -> 25,157 features. (3) The log2FC pseudocount was `min(positive)/2` recomputed per feature per contrast, producing |log2FC| up to 29.5 and — since q ties at the attainable floor — silently ordering every shortlist the project produced. (4) The media-blank rule used unpaired group means with an inert pseudocount of 1.0 (the smallest positive peak area in the table is ~1.4e4); measured against a blank-vs-blank null it had a **~60% false-pass rate**, and a split-half of the blanks passed MORE features than the real rule. Pairing on (plate, replicate) with an LOD pseudocount gives 1,806/2,959 real and **0/1 false**. (5) `mannwhitneyu(method="auto")` mixes nulls — exact for tie-free features, asymptotic for tied ones — so zero-inflated features could attain smaller p than perfectly separated dense ones.
- **Why it matters**: The deepest lesson is (6), which is not a bug but a reporting error: at n=5v5 the minimum attainable two-sided p is `2/C(10,5)=7.94e-3`, so BH can only call anything when `k >= p_min*m/q` ~ 16% of features separate perfectly AT ONCE. `n_significant` is therefore a step function of the feature universe. `dendrobatidis_spore_Sporangium_vs_spore_Mature` reads 5,507 significant on 38,547 features and **0** on 25,157 while sitting at **24.0x** the null separation rate in both. Threshold-free complete-separation enrichment shows all 12 within-matrix stage pairs are enriched 3.0-42.6x and NOT ONE is BH-callable — so "Sporangium and Mature are indistinguishable", the premise of the entire stage-collapse design, was never supported. Also note `method="asymptotic"` is the wrong fix: its 5v5 floor is 1.219e-2 vs the exact 7.937e-3, 1.5x conservative, enough alone to drive a contrast 5,507 -> 0.
- **Resolution**: `build_ordination_table.py` (blank split + artifact filter + corrected docstring), `mwu_exact.py` (full conditional enumeration; validated to max|diff|=0.0 vs scipy exact on tie-free 5v5, 1.1e-16 at 5v10, and handles the ties scipy's exact method refuses — note the `(1+x)/(1+n)` convention must NOT be used for an enumerated null, it re-inflates the floor to 1.19e-2), `separation_enrichment.py` (threshold-free statistic + BH-callability threshold per contrast), `background_subtraction.py` (paired-by-plate; pairing is on (plate, replicate) NOT `companion_of`, which on a `*C_liq` row names the *spore* sample), `lifestage_trend.py` (1,000-shuffle permutation null; `passes_media_blank` removed from spore strata since no spore process blank exists). F-002 amended, F-003 partially retracted. Full write-up in `CORRECTED_REANALYSIS_REPORT.md`.
- **Tags**: metabolomics, media-blank, analytical-design, small-n, benjamini-hochberg, permutation-test, exact-test, artifact-filter, critical-defect, everything-bagel

### 2026-09-02 — The blank-clearing "secreted" peptides are proline-rich at casein/gelatin levels: the secreted metabolome is dominated by medium proteolysis

- **Category**: analytical-design / biological interpretation
- **What happened**: After the corrected cascade (blanks removed, artifacts filtered, paired blank rule, exact null, MS2 gate) the defensible liq-enriched shortlist is small — Bd 90, Bsal 139 features with both a cleared media blank and an acquired MS2 — and nearly single-class: 56/90 and 102/139 are SIRIUS "Amino acids and Peptides", with the high-confidence structures being short proline-rich peptides (Val-Leu-Pro-Val-Pro, Pro-Val-Val-Pro, Tyr-Pro-Phe-Pro, Val-Val-Pro-Pro-Phe, Ala-Pro-Glu-Ala-Val). Parsing residue composition from the SIRIUS names (rejecting 43/62 Bd and 72/103 Bsal names as non-peptide rather than guessing) and binomial-testing Pro(+Hyp) frequency: **Bd 24.3% (27/111 residues), Bsal 16.9% (34/201)**. Both are consistent with beta-casein (~17%) and collagen/gelatin (~22%) and both **reject an average-proteome origin (~5%) at p=5.8e-12 and p=5.3e-10**.
- **Why it matters**: Bd's medium is 1% tryptone (casein digest) and Bsal's is 50% TGHL (tryptone/gelatin hydrolysate), both exceptionally proline-rich substrates. So even after blank-clearing, the dominant "secreted" signal is most consistent with fungal proteolysis of MEDIUM PROTEIN, not secondary-metabolite biosynthesis — and Tyr-Pro-Phe-Pro is a beta-casomorphin-region fragment of beta-casein. This converges with the repo's strongest comparative-genomics result, the MEROPS **M36 fungalysin expansion in Bsal** (328 M36 hits vs 39 in Bd; 233/247 secreted protease candidates), which predicts exactly this activity. Consequence for the project goal: compound-to-gene linkage is not achievable at identity level with this design, because the top hypothesis (NRPS peptide) and the top confounder (fungus-modified medium peptide) are the same molecules and no statistic on this dataset separates them. The decisive fix is experimental — a defined or 13C/15N-labelled medium, plus a spore-pellet process blank.
- **Resolution**: `analysis/differential_features_primary/scripts/peptide_origin_test.py` + `peptide_origin/`; §6 of `CORRECTED_REANALYSIS_REPORT.md`. Caveat recorded: composition is inferred from SIRIUS names rather than MS2 fragment ladders, and SIRIUS's structure DB is biased toward known peptides, so this tests whether the CLASS is digest-dominated, not the origin of any single feature.
